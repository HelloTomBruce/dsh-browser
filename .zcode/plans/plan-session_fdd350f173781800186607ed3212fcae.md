# dsh-browser v0.7.0 定位与交互效率提升实施方案

## 背景与目标

实际使用中「查找元素、点击交互」在千差万别的前端页面上仍有提升空间。根因不在单点算法，而在三处：**往返次数多**（snapshot→find→click 三轮）、**失败反馈贫瘠**（抛裸错误，agent 只能重新快照）、**定位通道单一**（CSS/ARIA 之外无兜底）。本方案六期改造，每期独立 commit、独立可验证，按 M1→M6 顺序实施，M3 完成后为天然效果验证点。

已核对的关键代码事实（方案以此为基准）：
- `resolveTargetLocator`（`src/browser/session/target.ts:34`）是全部交互工具的唯一定位入口，L188 的 `selector === undefined` 抛错点是挂接语义分支的自然位置；
- `findInteractive` 是 `src/browser/tools/inspection.ts` 的模块私有 const（L126-206），含去空白子串匹配与候选收集，可抽出复用；`assignRefs`（L213）已导出可增量注册 ref；
- SoM（`injectSomOverlay` L487）返回 `marks: {id, role, name}[]`，**不含 selector/坐标**；CDP screencast metadata（deviceWidth/deviceHeight）已透传到 `screencastManager.getLastFrame()` 但从未被消费；
- `walker.ts` 遍历不进 shadowRoot、`cssPath` 沿 `parentElement` 上溯在 shadow 边界断裂（L137-148）；`session.ts:190` 的 `framenavigated` 一律 `clearPageRefs`；
- 契约约束：`test/output-contract.test.ts` 要求所有工具声明 outputSchema 且返回值通过严格校验；`test/toolset.test.ts` 硬编码 37/24 工具数；click 的 outputSchema 是封闭 3 字段（clicked/url/title），新增返回字段必须同步扩展 schema。

## M1 意图优先语义定位（`what` 参数 + find 打分）

目标：`browser_click { what: "登录" }` 一次调用替代 snapshot→find→click 三轮；零命中返回带分数候选而非裸错误。

1. **新建 `src/browser/session/semantic.ts`**（避免 target.ts↔inspection.ts 循环依赖）：
   - 从 inspection.ts 抽出 `findInteractive` 主体，改造为 `scanInteractive`（injectWalker 注入）：入参 `{query, scope?, limit}`，输出 `{matches: [{role, name, selector, text, visible, inDialog, score, ancestors[]}], candidates[]}`；
   - 打分算法（页内）：query 按 CJK 单字 / `[a-zA-Z0-9_-]+` 分词；字段权重 name 3 / testid 2 / id 2 / text 1 / role 1；多 token 全部命中（AND）才入选，按总分排序；保留现有去空白归一化（`antd「确 定」`场景）；`exact` 语义不变；
   - `resolveSemanticTarget(page, what, opts): Promise<TargetResolution | { candidates: top5 }>`：页内扫描 → 命中多个时弹窗内优先（复用 `getActiveDialog`）→ 可见优先 → 用 `assignRefs` + `pageRefsOf`/`setPageRefs` 把命中元素注册成正式 ref（增量续号）→ 返回标准 `TargetResolution`（带 matchedCount/visibleCount，clickTool 的多命中诊断无缝工作）；零命中先做一次 `getByRole` + `buildFlexibleTextPattern` 二次尝试，仍零命中返回候选。
2. **`target.ts`**：ref 分支、row 分支之后、selector 检查之前插入 `what` 分支（`args.what` 且 selector/ref/row 均缺省时调用 `resolveSemanticTarget`）。
3. **`definitions/interaction.ts`**：click/type/press/select 四个工具的 parameters 增加 `what: { type: "string" }`（保持 `additionalProperties: false`）；click/type 的 outputSchema 增加可选 `candidates` 数组字段（仿 find 的 suggestions 风格）。
4. **`tools/interaction.ts`**：`clickTool`/`typeTool` 零命中时把候选表放进返回值（不抛错时）与错误消息（抛错时）；顺带把 click schema 里缺失的 `force`/`humanize` 属性声明补上（代码已读这两个参数但 schema 未声明）。
5. **`index.ts` systemPrompt**：两版 prompt 均加一句「优先用 what 意图定位，零命中会返回候选表」。
6. **测试**：新建 `test/semantic.test.ts`（打分纯逻辑 + mock page stub 的 resolveSemanticTarget，stub 模式照抄 `test/target-resolver.test.ts`）；`test/find.test.ts` 回归；output-contract 更新。

## M2 视觉定位通道（bbox ref 兜底 + mark 点击 + SoM 失败契约）

1. **RefEntry 增 `rect?: {x,y,w,h}` 与 `scroll?: {x,y}`**（`types.ts` L115-124）：`buildAriaTree` 注册 ref 时同步记录 `getBoundingClientRect()` 与 `scrollX/Y`（仅视口内元素）。
2. **`target.ts` ref 分支降级链末尾加坐标兜底**：路径校验与 getByRole 两级降级都失败后，若 entry 带 rect 且页面未导航（navSeq 一致），按 `rect + 当前 scroll - 快照 scroll` 修正坐标 → 页内 `elementFromPoint` → 用 walker `describeElement` 校验 role/name 与 entry 相似（role 相等且 name 包含或 LCS ≥ 阈值）→ 命中则以该元素的 cssPath 构造 locator 返回；不相似则维持原「ref 已失效」错误。
3. **SoM mark 点击**：`injectSomOverlay` 的 marks 增补 `selector` 与 `rect`；`screenshotTool(som: true)` 后把 marks 存入 per-page `markRegistry`（WeakMap<Page, Map<number, MarkEntry>>，导航失效）；click 增 `mark: integer` 参数，target.ts 加对应分支（markRegistry 查 → selector 定位 → 同 ref 的防漂移校验）。
4. **SoM 失败契约（多模态看图定位）**：`resolveSemanticTarget` 零命中时，若 `config.somFallback !== false`（新配置键，默认 true），自动截一张 SoM 视口截图，候选返回值附 `{ vlm: { screenshot: 路径, marks: [{id, role, name}] } }`，模型看图后可 `click { mark: N }` 一次往返完成定位。仅失败路径触发，正常调用零开销。
5. **测试**：`som.test.ts` 扩展（marks 结构）、`target-resolver.test.ts` 补坐标兜底与 mark 分支、output-contract 更新。

## M3 面板点选教学（browser_pick_element）

复用 confirm 的「挂起-轮询-面板提交-超时」骨架 + pause 的「超时不抛错」语义。坐标换算公式（已验证可行）：`cssX = imgPx * metadata.deviceWidth / naturalWidth`（elementFromPoint 收视口相对坐标，无需 scroll 换算）。

后端 4 处：
1. `session/collaboration.ts`：仿 PendingConfirm 新增 `PendingPick {id, instruction, startedAt, deviceWidth?, deviceHeight?}` + `set/get/resolvePick/clearPendingPick`（resolve 按 id 匹配防并发误放行）；
2. `tools/collaboration.ts`：新增 `pickTool`（克隆 confirmTool L182-229 骨架）：`setPendingPick`（快照 `screencastManager.getLastFrame()?.metadata`）→ 500ms 轮询 → resolve 后坐标换算 + `elementFromPoint` + `describeElement` → 返回 `{picked, selector, hint(SelectorHint 兼容 healCandidates), role, name, text, url, title}`；超时返回 `{picked: false}` 不抛错；
3. `ui.ts`：`/confirm` 块后加 `/pick` GET（轮询 pending）/POST（`{id, x, y, imgW, imgH}`，校验链照抄 /confirm + /runs/rerun）；
4. `definitions/collaboration.ts`：注册 `browser_pick_element`（timeoutMs 默认 600s），加入 `register.ts` 的 `CORE_TOOLS`。

前端 5 处：`types.ts` 加 PendingPick；`api.ts` 克隆 fetchPendingConfirm/submitConfirmDecision 为 pick 版本；新建 `hooks/usePickPolling.ts`（逐行克隆 useConfirmPolling：1s setTimeout 链、3 次失败退 15s）；`InspectionModal.tsx` 大图 img（objectFit: contain，L110-127）加 onClick：`getBoundingClientRect + naturalWidth/Height + contain letterbox 几何`换算出 JPEG 像素坐标回调，等待点选时 `cursor: crosshair`；`FloatingOverlay.tsx` 挂 hook、向 FloatingPanel 传 pendingPick 渲染琥珀色横幅（仿暂停横幅 L119-144）。

测试与契约：toolset.test 工具数 37→38、core 24→25；output-contract 覆盖新工具；`test/pick.test.ts`（状态机 + 换算纯函数单测）；README/systemPrompt 更新。

## M4 Shadow DOM 穿透

1. **walker.ts**（单一来源，一处改全局受益）：`__walkerCore` 新增 `deepChildren(el)`（`Array.from(el.children)` + open `el.shadowRoot?.children`）与 `composedParent(el)`（`parentElement ?? (rootNode instanceof ShadowRoot ? rootNode.host : null)`）；`cssPath` 上溯改用 composedParent 跨 shadow 边界（host 链 + ` > ` 拼接——playwright css 引擎对 open shadow root 是穿透的，join 语义不变，但 nth-of-type 段在 shadow 内按 shadow 父计数，与穿透引擎语义一致，需 e2e 验证）。
2. **消费方换 deepChildren 遍历**：`buildAriaTree` / `findInteractive`(scanInteractive) / `injectSomOverlay` / `installHumanRecorder` / `pickElementInjector` / `describeTarget` 的 DOM 遍历入口。closed shadow root 不可见（文档注明）。
3. **验证**：playground 新增 shadow-dom 测试页（自定义元素内嵌按钮/输入框，两层嵌套 shadow）；新建 `scripts/test-dev-server-shadow.ts`（照抄 test-dev-server-enterprise.ts 模式）断言快照/find/click/指纹在 shadow 内元素上全链路可用。
4. 单测：walker 纯逻辑无法在 node 环境验证 DOM 行为，此项以 e2e 脚本为准；`pnpm test` 不受影响。

## M5 SPA ref 软失效重锚定

1. **`cache.ts`**：新增 per-page `navSeq` 计数器（`bumpPageNav(page)` / `pageNavSeq(page)`，WeakMap 实现）；`RefEntry` 增 `navSeq` 字段；`setPageRefs` 写入时打当前 navSeq。
2. **`session.ts:190`**：`framenavigated` 主 frame 分支的 `clearPageRefs(page)` 改为 `bumpPageNav(page)`（注册表保留，标记过期）。
3. **`target.ts` ref 分支**：`entry.navSeq !== pageNavSeq(page)` 时先重锚定——重跑 `buildAriaTree`（scope body，2s 上限）→ 纯函数 `remapRefs(oldRefs, freshScan)` 按 `role 相等 && name 去-空白相等（其次 LCS ≥ 0.6）` 匹配，命中的 ref **沿用原编号**更新 selector/rect/navSeq，未命中的删除——再继续原解析；重锚定失败（整页跳转场景）走原「ref 已失效」路径。每次导航只重锚定一次（成功后 navSeq 对齐）。
4. **配置**：`refReanchor: true`（新键，默认开，false 时回退 M5 前行为即导航即清空）。
5. **测试**：`remapRefs` 纯函数单测（命中/名称漂移/消失/整页变化）；`test/target-resolver.test.ts` 补 navSeq 分支；schema/README 更新。

## M6 点击效果验证 + 定位失败遥测

1. **`primitives/dom.ts` 新增 `collectChangeDigest(page, {windowMs=600, maxItems=10})`**：注入 MutationObserver 短窗口收集 added/removed/attribute 变化元素的 cssPath（去重截断），返回 `{mutations: string[], domChanged: boolean}`（改造自 waitForDOMQuiescence 的 observer 模式）。
2. **`clickTool` 增 `effect: boolean`（默认 false）**：开启时点击后收集摘要 + URL 是否变化 + `networkEntries(profile)` 按点击时间戳过滤的新增请求，返回值加 `effect: {domChanged, mutations, urlChanged, newRequests}` 字段（outputSchema 同步扩展）。
3. **semantic 多候选 + effect 无变化自动换候选**：`what` 解析出多个候选时（matchedCount>1），首个点击后 `effect` 开启且摘要为空 → 自动点击次候选（最多 1 次），返回值标注 `switchedCandidate: true`。
4. **tracer 定位失败分类**：`session/tracer.ts` 的 `StepTraceEntry` 增可选 `locationFailure?: {phase: zeroMatch|ambiguous|dialogOverlay|staleRef|coordinateMiss|shadowOnly, candidates: number, dialogActive: boolean, hasShadow: boolean}`——click/find 失败路径 best-effort 页内探测填充（一次 evaluate，失败静默），随 `/browser/timeline` 自然透出，为后续按真实流量排序优化提供数据。
5. **测试**：`test/effect-verify.test.ts`（digest 收集器 mock page）、tracer 字段单测、output-contract 更新。

## 实施顺序与验证策略

按 M1→M2→M3→M4→M5→M6 顺序，每期一个 commit（feat 语义化提交）。每期完成跑 `pnpm verify`（typecheck + biome lint + vitest 全量）；M2/M3/M4 涉及真实浏览器行为的，另跑 playground e2e 脚本（dev-server + 对应 test-dev-server-*.ts）。M3 完成后为天然验证点：语义定位、视觉通道、面板点选三项可整体试用后再决定是否继续 M4-M6。

## 风险与对策

- **outputSchema 收紧风险**（宿主严格校验，schema 未声明字段会导致工具报错）：所有返回值变更必须先扩 schema，output-contract 测试把关；
- **find 打分改动向后兼容**：`exact` 语义保留，打分只影响排序与零命中候选，find.test.ts 回归；
- **shadow 穿透无法单测**：walker 页内逻辑依赖真实 DOM，全部走 playground e2e，不阻塞 vitest；
- **mark/rect 注册表内存**：WeakMap + navSeq 失效，与现有 refRegistry 同生命周期，量级可控（≤ maxRefs）；
- **坐标兜底误点风险**：仅作 ref 链最后一级，且带 role/name 相似校验，校验不过维持原报错。
