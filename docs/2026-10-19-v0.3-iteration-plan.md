## F1 — `browser_pause_for_human` 人工接管原语(P0,已实现)

`browser_wait_for_login` 的通用版:agent 把控制权暂时交还给用户(验证码/
二次确认/人工复核)。

```ts
browser_pause_for_human({
  instruction: "请输入短信验证码并提交",
  successSelector: ".dashboard",   // 或 successUrl;都不给则 URL/页面内容签名变化即完成
  timeoutMs: 300000,
})
// → { completed, status: "completed"|"timedOut", instruction, detail, waitedMs, url, title }
```

- instruction 显示在实时画面面板(琥珀色横幅,/status 附 pause 字段);
- 默认完成条件 = URL 变化 **或** 页面内容签名变化(href + innerText 长度 +
  交互元素数),比登录场景的「URL 跳转」更宽,覆盖弹层/验证码;
- 超时不抛错返回 completed:false;已注册 stepImpls,回放到该步即暂停等人;
- `runPauseOnPage` 导出为独立函数(page 参数注入),fake page 即可单测。

## F2 — `browser_confirm` 敏感操作审批(P0,已实现)

```ts
browser_confirm({ reason: "提交白名单表单,产生线上数据变更", tool: "browser_click",
                  args: { selector: "#submit" }, timeoutMs: 60000 })
// 用户允许 → { decision: "allowed", id, reason, waitedMs, detail }
// 拒绝/超时/被新审批取代 → 抛错「敏感操作被拒绝: …」(fail-closed)
```

- 审批卡片(红色横幅 + 允许/拒绝按钮)推送到实时画面面板,独立
  `GET/POST /confirm` 端点(1 秒轮询,id 幂等防错批);
- **fail-closed**:拒绝、超时(默认 confirmTimeoutMs=60s)、被并发新审批取代
  三种情况全部抛错,live 与 replay/batch 统一按失败处理,无需回放内核改动;
- 配置 `confirmMode: off|manual`(默认 off 零行为变更;manual 时 systemPrompt
  指示 agent 敏感动作前必须审批且不得绕过)。

## F3 — 人机混合录制(P1,已实现)

录制(`browser_record start → stop`)期间,用户在浏览器窗口的手动操作自动
进录制 buffer:

- 页内常驻注入(`exposeBinding` + `addInitScript` 每次导航自动重装,node 侧
  仅录制中生效):可交互元素 **click**、输入框 **change**(提交时记当前值,
  非逐键)、原生 select **change**(记选中文本);
- 映射为 `browser_click/type/select` 步骤,带 formatVersion 2 选择器指纹,
  `meta.source: "human"` 标记(随录制文件持久化);
- **回声去重是核心难点**:Playwright 工具事件 `isTrusted=true` 页内无法区分
  人手,register 包装层在 agent DOM 工具执行前后各打 `noteAgentAction`,
  1.5s 窗口内的页内回传丢弃;
- file input 与空输入跳过(无法可靠回放);save/stripReads/vars/自愈链路
  零改动即支持混合序列。

## F4 — 面板双向化(P1,已实现)

实时画面面板从单向观察升级为双向协作:

1. **🎯 人选元素**:大屏「点选元素」→ `POST /pick` 注入一次性 click 捕获
   (preventDefault + 稳定 CSS 路径),面板 500ms 轮询取结果,结果条展示
   selector + tag/role/name + 一键复制;
2. **操作预告高亮**:browser_click/type/select/press 执行前,目标元素
   (selector 直传或 ref 经注册表反查)琥珀色描边 + `agent: click` 标签
   ~1.5s,fire-and-forget 绝不阻塞操作时序;
3. **内嵌报告**:「最近回归」行可点击,新模态 iframe 加载
   `GET /runs/report`(默认最近运行来源,?source= 过滤),复用
   renderHtmlReport 展示趋势/失败明细/自愈清单。

## F5 — `browser_find` 语义元素定位(P0,已实现)

```ts
browser_find({ query: "提交", exact: false, scope: "#form" })
// → { found: 1, matches: [{ ref, role, name, ancestors }], scanned, url, title }
// 零命中 → { found: 0, suggestions: [{ role, name, score }] }(不抛错)
```

- 页内 walker(与 aria 快照同一套 role/name/cssPath 语义)按名称包含/精确
  匹配(或 id/data-testid 全等)查找,只返回命中 ref + ancestors 区域链,
  不输出全量树——大页面定位单目标 token ≤ 全量 aria 快照 5%;
- ref **增量续号合并**进既有注册表(旧 ref 不失效);多命中全返回(≤10 条)
  附区分信息;零命中返回 LCS 相似度 top5 候选;
- systemPrompt 已调整为定位首选(全页结构才用 aria snapshot)。

## F6 — snapshot 区域提取 + 增量重读(P2,已实现)

- `scope`(CSS 选择器):text/aria 两模式都只对命中容器提取,未命中抛错;
- `since`(上次返回的 contentVersion):版本命中且内容未变 →
  `{ unchanged: true }`;变了 → 行级 diff(diffLines 掐公共前缀/后缀)只返回
  变化行 `{ diff: true, changedFrom, removed }`;版本过期回落全量标
  `stale: true`;
- per-page 单调版本号,WeakMap 缓存最近一份 text/aria 内容;表格翻页场景
  实测页头页脚噪声被掐掉,只回数据行;不传参数行为与 v0.2 零差异。

## F7 — `browser_context` 隔离上下文(P1,已实现)

```ts
browser_context({ action: "new", name: "biz", url: "…" })  // list | new | switch | close
```

- 同一浏览器进程内独立 BrowserContext(cookies/storage 完全隔离)的"标签组",
  多账号并行验证 / 干净会话抓取;
- 页注册进 profile 标签表,既有 tabs/getPage/activePage 与全部工具零改动;
- switch 激活该组存活页(全关则原 context 新开,登录态仍在);close 整组
  关闭并回退 activeId;
- 持久模式(userDataDir)明确拒绝引导用 profiles;README 写明
  context(临时并行)与 profile(持久配置)分工。

## F8 — `browser_doctor` 健康诊断(P1,已实现)

不启动浏览器的一次性体检:executablePath 存在/可执行(X_OK)、channel 策略 +
捆绑 chromium 兜底、playwright-core 可用性、userDataDir 写权限、工作区基准
目录(标注解析来源)、截图/下载/基线目录写权限、会话状态、面板 API 可达性
(index.ts 注入本机 /status 探针)。输出
`{ checks: [{name,ok,detail,advice?}], summary:{ok,passed,failed} }`,
失败项附修复建议。

## F9 — `toolset: core | all` 渐进披露(P2,已实现)

- 默认 `all`(36 个,零行为变更);`core` 只注册 24 个高频核心工具,12 个
  低频(record/replay/report/extract/form×3/profile/context/cookies/back/
  reload)不注册、不进 systemPrompt;
- systemPrompt 拆 FULL/CORE 双变体(core 约为全量 40% token,明示未注册
  工具与切回方法);人机协作原语全部保留在 core;
- 回放走内部 stepImpls 不依赖工具注册,core 模式下已有录制仍可回放。

## 风险与对策(落地后回看)

| 风险 | 对策(实际落地) |
