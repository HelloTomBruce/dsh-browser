# dsh-browser-view v0.2.0 迭代方案:回归测试闭环 + 结构化抽取 + Agent 效率

> **状态**:已实现(2026-10-19,pnpm verify 全绿,118/118 测试通过)。
> 落地与方案的差异:ARIA 快照用自写页内 walker(方案既定);像素 diff 走页内
> canvas(零依赖);录制格式升级 formatVersion 2(meta 选择器指纹 + `{{占位符}}`)。
> 工具数 28 → 31(batch / extract / report),版本号升至 0.2.0。
> **范围**:7 项功能一次性实现、一个版本发布(v0.2.0),不分阶段上线;仅按依赖关系
> 排列实施顺序。延续既有原则:**运行时零新增第三方依赖**(仅 playwright-core),
> 所有 schema 变更向后兼容(只增不删)。

## 目标与主线对应

| 主线 | 本迭代交付 |
| --- | --- |
| 前端回归测试 | F3 视觉回归断言、F4 选择器自愈、F5 录制参数化/数据驱动、F6 回归报告 |
| 网站信息获取 | F7 `browser_extract`(规则抽取 + 分页 + CSV/JSONL 落盘) |

## 功能清单与依赖关系

```
F1 ARIA 快照/ref ──┐(ref 也被 F4 自愈复用为定位候选)
F2 batch(复用 runReplay 内核,独立) ── F6 报告(记录 batch/replay 运行)
```

## F1 — ARIA 快照 + ref 引用交互

### 接口

```ts
browser_snapshot({ mode: "aria" })
// → { url, title, tree: string, refs: number, truncated: boolean }
// tree 形如:
// - navigation "主导航"
//   - link "首页" [ref=e1]
// - main
//   - textbox "用户名" [ref=e2]
//   - button "登录" [ref=e3]

browser_click({ ref: "e3" })            // ref 与 selector 二选一
browser_type({ ref: "e2", text: "..." })
browser_select({ ref: "e5", option: "杭州市" })
browser_press({ ref: "e2", key: "Enter" })
browser_assert / browser_wait_for 的 count 条件也接受 ref
```

### 实现([tools.ts](../src/browser/tools.ts) + [session.ts](../src/browser/session.ts))

1. **页内树构建**:不用 `locator.ariaSnapshot()`(playwright-core 1.49 的 ref 生成
   不稳定,且要控制输出体积),自写 evaluate walker:遍历 DOM,按
   implicit/explicit role 归类(link/button/textbox/checkbox/combobox/heading/
   navigation/main…),折叠无语义容器(div/span 无角色直接穿透),输出缩进树;
   只对**可交互元素**分配 `e1..eN` ref。
2. **Ref 注册表**(session.ts,per-tab):`Map<ref, { role, name, selector }>`,
   selector 为生成时计算的稳定 CSS 路径(优先 `#id` → `[data-testid]` →
   nth-of-type 路径)。`page.on('framenavigated')` 与新 snapshot 调用时清空。
3. **ref 解析**(供 click/type/select/press 共用的 `resolveTarget(args)`):
   先试存储的 CSS 路径并校验 role/name 仍匹配(防 ref 漂移),不匹配则降级
   `getByRole(role, { name })`;均失败报错「ref 已失效,请重新 snapshot」。
4. **体积控制**:树超 `maxTextChars` 截断并 `truncated: true`;`maxRefs` 上限 200。
5. 原 `mode: "text"`(默认)行为完全不变。

**验收**:典型管理后台列表页,`mode:"aria"` 输出 token 量 ≤ text 模式 40%;
用 ref 完成「输入+点按钮」全流程 2 次调用;导航后旧 ref 报「已失效」。

## F2 — `browser_batch` 动作批处理

### 接口

```ts
browser_batch({
  steps: [
    { tool: "browser_click", args: { ref: "e3" } },
    { tool: "browser_wait_for", args: { condition: { text: "已加载" } } },
    { tool: "browser_type", args: { selector: "#kw", text: "dsh", submit: true } },
  ],
  failFast: true,
})
// → { total, passed, failed, results: [{ index, tool, ok, error? }], summary }
```

### 实现

- **内核零新代码**:`batchTool` 直接复用 `runReplay()`([tools.ts:914](../src/browser/tools.ts#L914)),
  在 [register.ts](../src/browser/register.ts) 注入同一个 `stepImpls`。
- **防递归**:步骤内禁止 `browser_batch / browser_replay / browser_record`,
  遇之该步直接报「不允许嵌套」。
- batch 整体作为**一条**操作轨迹记录(录制时记为单个 browser_batch 步骤,
  回放原子性好);批内步骤不再逐条进 testLog。
- 返回结构复用 replay 的 outputSchema 形状,契约测试成本低。

**验收**:登录流程「填 2 字段 + 点登录 + 等跳转」从 4 次往返缩到 1 次;
录制 batch → replay 结果等价。

## F3 — 视觉回归(基线 + 像素 diff 断言)

### 接口

```ts
browser_screenshot({ baseline: "login" })          // 存基线,不受清理策略约束
browser_assert({
  visual: { baseline: "login", threshold: 0.1, maxDiffRatio: 0.005 }
})
// → 通过 / 抛错(附 diffRatio、diff 图路径、当前截图路径)
```

### 实现(零新增依赖:页内 canvas diff)

1. **基线存储**:`<workspace>/.dsh-browser/baselines/<name>.png`(配置 `baselineDir`
   可改);`safeName()` 防路径穿越;`browser_screenshot { baseline }` 写入该目录,
   返回值标 `baseline: true`。**不进截图清理范围**([session.ts](../src/browser/session.ts)
   的 sweep 只清 screenshotDir,天然隔离)。
2. **比对**:新开一个隐藏 about:blank 页,把基线(读文件转 data URL)与当前截图
   都画进 canvas,逐像素比较:
   - 尺寸不同 → 直接失败并报尺寸;
   - 逐像素 ΔRGB,超过 `threshold`(0–1,单通道归一化亮度差,语义对齐 pixelmatch)
     计为差异像素;`diffRatio = diffPixels / total` 超 `maxDiffRatio` 判失败;
   - 差异像素标红生成 diff 图,`canvas.toDataURL` 落盘到
     `.dsh-browser/screenshots/visual-diff-<baseline>-<ts>.png`(受清理策略管)。
3. **抖动抑制**:支持 `visual.mask: ["#clock", ".ad-banner"]` —— diff 前把命中
   选择器在当前页的 bounding box 区域在两图上同步填白。
4. assert 失败沿用既有证据机制(错误消息含 diff 图路径)。

**验收**:改动一个按钮颜色 → diffRatio > 0 且 diff 图红区定位正确;
时间戳区域加 mask 后断言通过;无基线时报错提示先用 `baseline` 截图。

## F4 — 选择器自愈(录制回放场景)

### 机制

1. **录制时采指纹**:[session.ts](../src/browser/session.ts) `recordCall` 之后,
   对带 `args.selector` 的步骤(click/type/select/press/upload),evaluate 采集
   元素指纹随步骤存档:
   ```json
   "meta": { "hint": { "testid": "login-btn", "role": "button", "name": "登 录",
                       "id": "submit", "text": "登 录", "tag": "button" } }
   ```
   录制文件升级 **formatVersion: 2**(旧文件无 meta,回放时跳过自愈,行为不变)。
2. **回放时降级链**:原 selector 失败(timeout 缩短到 `healTimeoutMs`,默认 3000,
   避免每步等满 30s)→ 依次尝试:
   `getByTestId` → `getByRole(role, {name})` → `getByText(text)` → `#id` →
   `tag:has-text(text)`;全部失败才报原错并附「已尝试的降级候选」。
3. **透明上报**:自愈成功的步骤在结果里标
   `{ ok: true, healed: true, via: "role+name", selector: "(原)", resolved: "(新)" }`,
   汇总里给 `healedCount` —— 提示用户去修录制,不静默吞掉漂移。
4. 配置 `selectorHealing: true`(默认开,仅作用于 replay/batch;live 工具不变,
   避免掩盖真实选择器错误)。

**验收**:把录制里的 `#rc_select_1` 改为失效 id 后,replay 经 `role+name` 自愈
通过且结果标 `healed`;指纹全失时错误消息列出尝试过的 5 个候选。

## F5 — 录制参数化 + 数据驱动回放

### 接口

```ts
// 保存时声明变量:把指定步骤的字段抽成 {{var}}
browser_record({ action: "save", name: "login",
                 vars: { username: "#3.args.text", password: "#4.args.text" } })

// 单次回放带变量
browser_replay({ name: "login", vars: { username: "a@x.com", password: "***" } })

// 数据集驱动:每行跑一次,结果按行聚合
browser_replay({ name: "login",
                 data: [{ username: "a@x.com", password: "1" },
                        { username: "b@x.com", password: "2" }] })
// → { runs: [{ row: 0, passed, failed, ... }, { row: 1, ... }], summary }
```

### 实现

- **save**:`vars` 的值是「步骤序号.args.字段」路径,save 时把该字段原值替换为
  `{{username}}` 占位符后落盘;返回值回显替换数。
- **replay**:执行前对 steps 深拷贝做 `{{var}}` 字符串模板替换(全字符串替换,
  不限 type 步骤——URL、文件名也可参数化);存在未提供值的占位符时**直接报错
  并列出缺失变量**(不做空串替换,防脏数据)。
- **data 模式**:对每行依次 `runReplay`,行间不共享断言状态;单行失败不中断
  后续行(data 模式隐含 failFast-per-row);每行结果带 `row` 与该行数据回显
  (密码类值由用户在 vars 名里自行注意,不做自动脱敏,README 注明)。
- 数据集也可传文件:`dataFile: "testdata/login.csv"`(工作区相对路径,CSV 首行
  为变量名),插件解析为行数组。

**验收**:同一份登录录制,3 行 CSV 跑 3 次,汇总 3/3 通过;缺变量时报错
「缺少变量: password」;旧格式录制不带 vars 回放行为不变。

## F6 — 回归运行历史 + 报告

### 接口

```ts
browser_report({ action: "list" })                       // 最近运行
browser_report({ action: "show", runId: "20261019-1400" })
browser_report({ action: "export", format: "markdown",   // 或 html
                 file: "reports/regression.md" })        // 默认落工作区
```

### 实现

1. **运行记录**(session.ts):每次 `browser_replay` / `browser_batch` 完成即追加
   一条 run:`{ runId, ts, source, total, passed, failed, healedCount, durationMs,
   steps: [{index, tool, ok, error?, healed?}] }`,落盘
   `$DSH_HOME/.dsh-browser/reports/runs.jsonl`(append,单写者无并发问题;
   超 1000 条截断旧行)。
2. **报告生成**:export 聚合同名 source 的最近 N 次运行 → 通过率趋势、
   步骤失败 TopN、自愈步骤清单、失败截图索引,纯字符串模板生成 Markdown
   / 自包含 HTML(内联 CSS,无外部资源)。
3. **面板**(client/index.tsx,小改):状态行下加一行「最近回归:login 5/6 ✗ ·
   10 分钟前」,点击打开报告文件路径。
4. **定时回归**:不建调度设施,README 给出 `schedule_create` +
   `browser_replay` + `browser_report export` 的组合范式即可。

**验收**:连续 3 次 replay 后 export 出含趋势表与失败步骤明细的 Markdown;
面板显示最近一次结果。

## F7 — `browser_extract` 规则化抽取 + 落盘

### 接口

```ts
browser_extract({
  fields: [
    { name: "title",  selector: "h1" },
    { name: "price",  selector: ".price", attr: "textContent" },
    { name: "rows",   selector: "table tr", multiple: true,
      fields: [{ name: "name", selector: "td:nth(0)" }] },   // 嵌套行抽取
  ],
  next: ".pagination .next",   // 可选:翻页选择器
  maxPages: 5,
  format: "csv",               // json | csv | jsonl | markdown
  file: "output/prices.csv",   // 可选:落盘(工作区相对路径)
})
// → { rows: [...], pages: 2, file: "output/prices.csv", truncated: false }
```

### 实现

- **规则抽取,不含模型**:工具只做确定性 CSS/attr 抽取(textContent 默认,
  可指定 `href/src/value` 等 attr);语义化「给我文章要点」类需求留给
  agent(snapshot → jev_extract),README 写明这一分工与组合范式。
- **翻页循环**:每页抽取 → 点 `next` → `waitForLoadState` + 可选
  `waitAfterMs` → 直到 next 不存在/不可点或达 `maxPages`;跨页聚合 rows。
- **落盘**:csv(首行表头,值转义)/ jsonl(每行一 JSON)/ markdown(表格);
  路径经 `workspaceBaseDir` 解析 + 穿越检查(复用 upload 的校验逻辑)。
- 行数超 `maxRows`(默认 1000)截断并标 `truncated`。

**验收**:3 页列表抓全 30 行写 CSV;next 缺失时安全停止;file 路径
`../x.csv` 被拒。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| ref 漂移导致误点 | 解析时校验 role/name,不匹配即降级/报错,绝不盲点 |
