> sensitiveTools 显式加入);F2 面板重跑遇 agent 忙碌**置灰**(409);F5 走

## F1 — confirm 自动拦截(auto 模式)【P0,人机协作深化】

### 问题

v0.3 的 `confirmMode: manual` 是**软约束**:systemPrompt 指示 agent 敏感动作前
调用 browser_confirm,但 agent 可以不调用直接 `browser_click #submit`。信任
边界依赖模型自觉,不适合真正的高风险场景(支付、删除、线上变更)。

### 需求

新增 `confirmMode: "auto"`:宿主层**强制**在匹配敏感模式的动作前弹审批,
agent 无法绕过。

### 接口草案

```yaml
config:
  confirmMode: auto            # off | manual | auto
  sensitivePatterns:           # auto 模式的敏感判定(命中任一即拦截)
    - 'button:has-text("提交")'
    - 'button:has-text("删除")'
    - 'button:has-text("支付")'
    - '[role=submit]'
  sensitiveTools: [browser_click, browser_type, browser_form]  # 参与判定的工具
```

### 实现要点

1. 拦截点在 register.ts 包装层:PREVIEW_TOOLS 同一钩子处,click/type/form
   执行前先解析目标 selector/ref → 元素文本,与 sensitivePatterns 匹配;
2. 命中 → 复用 v0.3 的审批管线(session.setPendingConfirm + 面板卡片),
   允许才继续执行原工具,拒绝/超时抛错;未命中 → 直接执行(不逐点击弹窗);
3. 匹配在页内做(page.evaluate 对目标元素取 innerText/role/属性),复用
   human recorder 的元素信息提取;
4. **性能约束**:每步匹配是页内一次 evaluate(与 preview 高亮同量级),
   不可明显增加操作延迟;**已决:默认只拦 browser_click**(type 误报率高,
   需要拦输入类动作时显式加入 sensitiveTools)。
5. replay/batch 同样被拦截(安全闸对回放同样生效;数据驱动场景可配
   `confirmInReplay: false` 逃生口,README 注明风险)。

### 验收

- auto 模式下 agent 直接 click「删除」按钮 → 审批卡片弹出,拒绝则该步失败;
- manual/off 模式行为与 v0.3 完全一致;
- 非敏感点击(翻页、展开下拉)不弹窗、无感知延迟增加。

## F2 — 失败自动重跑 + 面板一键重跑【P1,回归闭环】

### 问题

回归失败后(尤其选择器漂移、偶发超时),需要用户手工发起
`browser_replay` 重跑;自愈只救选择器,救不了偶发失败(网络抖动、加载慢)。
面板「最近回归」只能看,不能操作。

### 需求

1. `browser_replay { retryFailed: N }`:整轮回放结束后,失败步骤自动重试
   N 次(重试沿用自愈链,步骤间加短退避);
2. 面板「最近回归」行与内嵌报告模态加「重跑」按钮 → 调用后端回放接口;
3. 重跑运行同样进 runs 历史(标 `retryOf: <runId>`),报告可见重试次数。

### 接口草案

```ts
browser_replay({ name: "login", retryFailed: 2 })   // 失败步骤各重试 2 次
// → { ..., retries: { attempted: 2, recovered: 1 } }
```

```ts
POST /runs/rerun { source: "login" }   // 面板按钮 → 后端触发 replay(等价 agent 调用)
```

### 实现要点

- runReplay 循环内在失败分支加重试(退避 500ms×n);failFast 语义保持
  (重试耗尽才停);
- /runs/rerun 端点调 replayTool(与 stepImpls 同路径);面板轮询
  /runs/latest 展示进度;**已决:agent 忙碌时按钮置灰**——rerun 需与 agent
  会话互斥(浏览器单会话,agent 正在操作时返回 409,面板据此置灰);
- 报告导出与 runs.jsonl 加 retryOf / retries 字段(只增)。

### 验收

- 偶发超时用例(注入一次 network 延迟)retryFailed:2 下整体通过,报告标
  recovered:1;
- 面板重跑按钮在 agent 空闲时可用、忙碌时置灰(409)。

## F3 — 增量快照历史版本【P1,效率深化】

### 问题

v0.3 的 since 只支持**最近一个**版本:agent 持着 v5 快照操作几步后再
since=5,缓存已是 v9 → 只能回落全量(stale)。翻页/轮询类任务里这个窗口
经常错过。

### 需求

per-page 保留最近 K(默认 5)个历史版本(text/aria 各一份),任意
since ∈ [latest-K+1, latest] 都能给出 diff;更旧的版本仍回落全量。

### 实现要点

- session SnapshotCache 由单版本改为环形数组(K 可配 `snapshotHistory`,默认 5,
  上限 20;内存上界 = K × maxTextChars ≈ 100KB/page,可接受);
- diff 语义不变(diffLines 掐前后缀),仅命中范围扩大;
- 兼容:since 过期仍标 stale 回落全量;不传参数零变化。

### 验收

- 5 次快照后 since=首版本仍能 diff;since < 首版本回落全量标 stale;
- 轮询抓取场景(每 3 秒快照一次、期间有其他快照穿插)token 总量对比
  全量重读下降 ≥60%。

## F4 — extract 字段建议【P2,易用性】

### 问题

browser_extract 需要手写 fields(CSS 逐字段),页面结构复杂时 agent 要
先 snapshot/eval 探查一轮再拼 fields,往返 3-4 次。

### 需求

`browser_extract { action: "suggest", scope?: "#list", sample?: 3 }`:
从命中容器的第一条记录(如表格首行/卡片)自动推断字段结构——单元格文本、
链接 href、img src——返回建议 fields + 样本数据,agent 确认/微调后直接
交给抽取模式。

### 验收

- 典型列表页一次 suggest 得到可用 fields(含嵌套行),再一次 extract 完成抓取,
  往返从 3-4 次降到 2 次;
- 推断失败(无规律结构)返回原因与容器内元素概览,不猜。

## F5 — cssPath / aria walker 副本收敛【P0,内部质量】

### 问题

`cssPath`(含 role/name 推断)在代码里有 **4 份内联副本**:
buildAriaTree、findInteractive、pickElementInjector(tools.ts)与
installHumanRecorder(session.ts)。evaluate 序列化不允许闭包引用,当初各处
内联是权宜;任何语义改动需要同步 4 处,已经埋着漂移风险(v0.3 期间每次都靠
注释互相提醒)。

### 需求

收敛为**单一来源**:

1. 把 walker 工具函数(roleOf/nameOf/cssPath/isVisible + INTERACTIVE/
   STRUCTURAL 集合)提取为一个**自包含序列化模块字符串**(单一函数源码,
   各注入点 `new Function`/模板拼接注入),一处定义、四处使用;
2. 保持各消费方的输出语义完全不变(aria 树/查找/拾取/录制回声四条链路
   的既有测试是回归网);
3. 顺带统一:find 的元素匹配、pick 的信息提取、human recorder 的指纹采集
   共用同一份元素描述结构。

### 实现要点与风险

- **已决:方案 A(构建期内联)**——tsdown 插件把 walker 源文件内联成字符串
  常量(build 时生成),运行时零开销、类型可检查;各注入点保持 evaluate
  序列化函数,仅**源码**来自共享常量;
- 风险:字符串模板的转义与 CSP(页内注入在严格 CSP 页面可能被拦)——
  CSP 敏感页面(pick/recorder 场景)在 F2 面板重跑验收时人工抽查一次
  (F6 暂不实施,真浏览器验证以手动抽查代替)。

### 验收

- `grep -c "function cssPath" src/` 结果 1(或仅构建产物 1 处);
- 全部既有测试(179+)零改动通过;aria/find/pick/recorder 四链路行为不变。

## F6 — 真浏览器冒烟测试【暂不实施】

已决:本迭代不引入真浏览器测试(CI 依赖本机浏览器的成本大于收益)。
页内逻辑(walker/自愈/审批/拾取)继续依赖零浏览器单测 + 面板手动抽查;
若后续线上暴露「页内脚本在真实页面/CSP 下失效」类问题,再重评此项。
